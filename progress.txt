## Codebase Patterns
- CLI uses argparse with subparsers for subcommands (scrape, analyze, rankings, status)
- Each command has a cmd_<name> function handler in main.py that imports and calls module functions
- Module functions are imported lazily inside command handlers to avoid import errors when modules are incomplete
- Database: Use `from db import get_connection` to get SQLite connections, DB file is `mr_books.db`
- All database tables use CREATE TABLE IF NOT EXISTS for idempotent initialization
- Scraper: Use `cloudscraper` instead of `requests` to bypass Cloudflare protection on marginalrevolution.com
- Scraper: Article entries are in `<article>` tags, title links have `rel='bookmark'` attribute
- Scraper: Pagination can be found via link text "Next" or by looking for `/page/N` in href
- Scraper: Post content is in `div.entry-content` class; use fetch_with_retry() for resilient requests
- Analyzer: Use lazy imports inside functions to avoid circular imports between db.py and analyzer.py
- Analyzer: spaCy model 'en_core_web_sm' is required; code auto-downloads if missing
- Deduplication: Use `find_or_create_book()` from db.py instead of get_book_by_title/insert_book for fuzzy matching
- Deduplication: `normalize_title()` strips articles ("the", "a", "an") and punctuation for comparison
- Deduplication: Uses rapidfuzz library with token_sort_ratio for 85% similarity threshold
- Sentiment: Use VADER via `vaderSentiment.vaderSentiment.SentimentIntensityAnalyzer`; compound score is -1 to 1
- Sentiment: Scores are stored at both mention level (book_mentions.sentiment_score) and book level (books.sentiment_score)
- Sentiment (Ollama): Use analyze_sentiment_ollama() with --use-ollama flag; calls localhost:11434, handles interview transcripts
- Interview Detection: is_interview_or_transcript() detects speaker tags; extract_tyler_opinion() filters to Tyler's sections only
- Pagination: Use is_valid_pagination_url() to validate next page links; filters out external domains and invalid URLs
- Parallel Scraping: Use ThreadPoolExecutor + RateLimiter class for concurrent fetching; collect results, write to DB sequentially
- Caching: posts.books_extracted_at tracks extraction completion; use get_posts_for_extraction() for incremental processing
- Fail-fast: Use check_ollama_available() at start when --use-ollama to avoid wasting time if Ollama unavailable
- Schema Migration: Use PRAGMA table_info() + ALTER TABLE ADD COLUMN for backwards-compatible migrations
- Full-context LLM: Use analyze_post_with_llm() with --full-context flag for single LLM call per post extracting books + sentiment
- Full-context LLM: Returns JSON array; use regex to extract [...] pattern when LLM adds extra text
- Full-context LLM: Use insert_book_mention_with_sentiment() to store sentiment directly with mention
